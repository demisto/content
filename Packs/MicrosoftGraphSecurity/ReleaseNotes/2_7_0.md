#### Integrations

##### Microsoft Graph Security

- Added support for incident and alert mirroring: incoming, outgoing, or both.
- Added the *Incident Mirroring Direction*, *Close Mirrored XSOAR Incident*, *Close Mirrored Microsoft Alert/Incident*, *Comment Entry Tag (to Microsoft)* and *Comment Entry Tag (from Microsoft)* parameters.
- Added the ***get-remote-data***, ***get-modified-remote-data***, ***update-remote-system*** and ***get-mapping-fields*** commands.
- Added mirroring of the alert *customDetails* in and out with the **Additional Data** field (`key: value` items).
- When *Close Mirrored XSOAR Incident* is enabled, incoming mirroring closes the Cortex XSOAR incident only if it is still open, and reopens it only if it is closed. Other updates, such as comments, no longer add a reopen entry to an incident that is already open.
- A Microsoft incident that is redirected (merged into another incident) closes the mirrored Cortex XSOAR incident as **Resolved**, with the target incident ID in the close notes.
- When *Close Mirrored Microsoft Alert/Incident* is enabled, closing in Cortex XSOAR sends only the `resolved` status and a close comment with the close reason and the close notes. The classification is sent only when the **Microsoft Graph Security Classification** field is changed.
- The **Microsoft Graph Security Classification** field is mirrored out for alerts and incidents, and is sent as the Microsoft *classification* and *determination*.
- The assigned user (*assignedTo*) is mirrored in only and is never sent to Microsoft.
- The incident name is mirrored in both directions. The ` - <incident ID>` suffix added to the Cortex XSOAR name is removed before the name is sent to Microsoft.
- The alert severity is mirrored in only and is never sent to Microsoft, as the Microsoft Graph alerts API does not allow updating the severity.
- A Cortex XSOAR **Critical** incident severity is not sent to Microsoft, as Microsoft incidents have no critical severity.
- Added a validation to the **Test** button that fails when the *Comment Entry Tag (to Microsoft)* and *Comment Entry Tag (from Microsoft)* parameters have the same value.
- Removed the *Germany* option from the *Azure Cloud* parameter, as Microsoft Cloud Germany was closed in October 2021.

#### Mappers

##### New: Graph Security Mapper - Incoming

- Added an incoming mapper for Microsoft Graph Security alerts and incidents, including the mirroring fields. It is the default incoming mapper of the integration.
- The Microsoft description is mapped to the **Description** field.
- The Microsoft classification and determination are mapped together to the **Microsoft Graph Security Classification** field.
- For alerts, the Microsoft classification is also mapped to the **Classification** field (mirrored in only).
- Comments are mirrored as War Room notes, not mapped to a field.
- The incident name is mapped as `<displayName> - <incident ID>`, the same format as fetch, so a name changed in Microsoft is updated in Cortex XSOAR.
- The existing **Graph Security Alert** incoming mapper is unchanged.

##### New: Graph Security Mapper - Outgoing

- Added an outgoing mapper for mirroring Microsoft Graph Security alerts and incidents. For alerts, the close notes are mapped so they are included in the close comment. For alerts and incidents, the **Microsoft Graph Security Classification** field is mapped to the Microsoft classification.
- The incident tags (*customTags*) are now mapped directly from the **Microsoft Graph Security Incident Tags** field, so clearing all the tags in Cortex XSOAR is mirrored to Microsoft. If you use a customized or duplicated outgoing mapper, manually change its *customTags* entry to the plain **Microsoft Graph Security Incident Tags** field (a simple mapping with no filters or transformers).
- The alert custom details (*customDetails*) are now mapped directly from the **Additional Data** field, so clearing the Additional Data in Cortex XSOAR is mirrored to Microsoft, even when other fields are changed in the same save. If you use a customized or duplicated outgoing mapper, manually change its alert *customDetails* entry to the plain **Additional Data** field (a simple mapping with no filters or transformers).

#### Classifiers

##### New: Graph Security Classifier

- Added a classifier that sets the incident type of fetched records to **Graph Security Alert** or **Graph Security Incident**.
