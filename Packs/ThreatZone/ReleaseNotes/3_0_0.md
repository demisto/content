#### Integrations

##### ThreatZone

- Updated the integration to use version **1.1.1** of the official *threatzone* Python SDK for all API traffic, authentication, retry logic, and response parsing.
- Updated the integration to target Threat.Zone platform **v3.2.0+** and SDK **1.1.1**.
- Updated the credential parameter to an encrypted *ThreatZone API Key* (**type 9**) and made the *Server URL* parameter mandatory with normalization for instance-root and */public-api* URLs, without a cloud fallback.
- Updated the sandbox presets to the Threat.Zone v3.2 environment identifiers (*linux-ubuntu_2204*, *macos-ventura*, and *android9*), and now load sandbox defaults from the ThreatZone metafield configuration API. Active API defaults are applied unless overridden by a command argument or *analyze_config*.
- Updated the Docker image to *demisto/threatzone-sdk:1.1.1.11256202* and removed the obsolete *os* argument from ***tz-get-behaviours***.
- Updated the error handling so SDK-typed exceptions are translated into structured War Room messages instead of raw tracebacks, and improved Cortex XSOAR 6.x runtime compatibility.
- Added support for expanded command coverage across the ThreatZone public API, including configuration discovery, open-in-browser and submission queries, detailed report sections, bounded telemetry, and file and media downloads.
- Added support for sandbox execution configurations, URL safe-browsing, and indicator, IOC, and matched-YARA filters.
- Added support for generated-YARA readiness polling and safe media filename validation, and restored streaming for SDK downloads to avoid buffering large files in memory.
- Fixed an issue where report retrieval could omit later pages of filtered indicators, IOCs, and matched YARA rules, including the legacy `ThreatZone.IOC` output.
- Updated the integration to preserve every existing command and top-level context path so existing playbooks continue to function. The legacy `ThreatZone.Analysis.LEVEL` and `ThreatZone.Analysis.STATUS` integer codes are retained by mapping the SDK enums back to the historical integers, the *modules* argument is kept as a validated compatibility no-op, and original War Room filenames are preserved for sandbox, static, and CDR uploads.

**Note:** Existing playbook YAMLs and external context references do not need changes. The internal shape of *ThreatZone.Submission* reflects the new public API schema because the upstream */public-api/submissions/{uuid}* endpoint replaced the legacy */get/submission/{uuid}* endpoint in Threat.Zone v3.2.0. Customers running against pre-v3.2.0 instances must pin to ThreatZone content pack **2.0.1** until they upgrade the platform.
