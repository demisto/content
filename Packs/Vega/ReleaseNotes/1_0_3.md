##### Vega Alerts

- Updated the Vega Alerts incident field description to reflect the behavior when **Include alert metadata on incidents** is enabled.

##### Vega Assets

- Updated the Vega Assets incident field type to a read-only grid with Type and Value columns.

##### New: Vega Assets Value

- New: Added the **Vega Assets Value** incident field to store raw asset data when assets are not split into typed rows.

##### New: Vega Comments Source

- New: Added the **Vega Comments Source** incident field to store unmodified Vega comments for mirroring and audit purposes.

##### Vega Data Sources

- Updated the Vega Data Sources incident field type to a read-only grid with a single Value column.

##### Vega Incident Status

- Updated the Vega Incident Status incident field select options to OPEN, IN REVIEW, ON HOLD, and RESOLVED.

- **Breaking Change:** Reduced the available select values from 9 to 4 (`OPEN`, `IN REVIEW`, `ON HOLD`, `RESOLVED`). Existing incidents using removed values or playbooks/automations that rely on them must be updated.

##### New: Vega Investigation Status

- New: Added the **Vega Investigation Status** incident field to track the Vega investigation lifecycle status (where NEW is shown as Pending in Vega).

##### Vega Last Updated

- Updated the Vega Last Updated incident field to support Vega Alert incidents and updated the description to clarify timestamp usage.

##### Vega MITRE ATT&CK

- Updated the Vega MITRE ATT&CK incident field type to a read-only grid with a single Value column.

##### Vega Observables

- Updated the Vega Observables incident field type to a read-only grid with a single Value column.

##### New: Vega Timeline Events Source

- New: Added the **Vega Timeline Events Source** incident field to store unmodified Vega incident timeline events as JSON.


#### Mappers

- Updated the Vega Mapper mapper logic for Vega Last Updated on alerts, Vega Investigation Status, Vega Alerts, Vega Assets / Vega Assets Value, and Vega Comments Source / Vega Timeline Events Source for incoming data.

#### Layouts

##### Vega Alert

##### Vega Incident

#### Integrations

##### Vega

- Deleted the **Enable Cortex XSOAR to Vega mirroring** parameter.

- Added support for **Fetch alerts and incidents by ID** parameter that when selected, other collect filters are ignored and only the ids below are fetched. an id already in cortex xsoar is created again.

- Added support for **Incident IDs to fetch** parameter that commaseparated incident uuids (id1,id2) to refetch missed records. used only when fetch alerts and incidents by id is selected.

- Added support for **Incident Mirroring Direction** parameter that choose the direction to mirror the incident: incoming (from vega to cortex xsoar), outgoing (from cortex xsoar to vega), or incoming and outgoing (from/to cortex xsoar and vega). none turns mirroring off. the direction is stored on each incident when it is fetched. changing this setting later does not change incidents already pulled.

- Added support for **Incident Investigation Statuses to fetch** parameter that the vega investigation statuses by which to filter incidents. if empty, all investigation statuses are fetched. new is shown as pending in vega. any custom values entered outside the available options are ignored and will not affect the fetch cycle.

- Added support for **Alert IDs to fetch** parameter that commaseparated alert uuids (id1,id2) to refetch missed records. used only when fetch alerts and incidents by id is selected.

- Added support for **Include alert metadata on incidents** parameter that stores full relatedalert metadata on each incident. this can make incidents large.

- Added support for **vega-get-alert-metadata** command that return vega alert metadata to the war room. pass one incident_id to load the alerts related to that vega incident. when run from a vega incident without incident_id, the investigation's related alert ids are used. when run from a vega alert, that alert id is used. the war room entry is a direct json object for one alert or an array for multiple alerts. each alert contains the ten highestpriority metadata fields. the result is not written onto the incident.

- Added support for **vega-reconcile-incidents** command that compare selected vega alert and incident uuids with cortex xsoar in a createdtime window and return the ids missing from cortex xsoar. only selected entities are queried. paste the lists into a vega instance that has fetch alerts and incidents by id selected.

- Added support for *alert_ids* argument in the **vega-get-alert-events** command.

- Updated the Docker image to: *demisto/python3:3.12.14.13495286*.
