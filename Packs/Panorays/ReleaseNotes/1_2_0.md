#### Integrations

##### Panorays Findings API

- Added support for ingesting findings from across your supplier (third-party) portfolio, so that critical supply chain findings raise incidents in Cortex XSOAR.
- Added the **Findings scope** parameter, which selects whether an instance fetches your own organization's findings or your suppliers' findings. Configure a separate instance for each scope.
- Added the **Supplier finding severities** parameter (default **CRITICAL**), which controls the severities that create incidents when fetching supplier findings.
- Added the **Supplier finding statuses** parameter (default **OPEN,REOPENED**), which excludes remediated (DONE) findings while still covering findings that were reopened.
- Added the **Date field to fetch by**, **Supplier segment IDs**, and **Supplier tags** parameters for narrowing which supplier findings are ingested.
- Added the **Supplier list cache TTL (hours)** parameter, which controls how often the supplier portfolio is re-enumerated.
- Added the **Maximum API requests per minute** parameter (default **120**) and client-side throttling, so that fetching across a large portfolio cannot exceed the Panorays rate limit of 150 requests per minute, which blocks the caller for one hour.
- Fixed an issue where list commands and fetches only returned the first page of results. The Panorays API is cursor paginated, but the integration sent an unsupported `page` parameter, which the API ignored.
- Added the **severity**, **status**, and **asset_name** arguments to the ***panorays-finding-list*** command.
- Deprecated the **page** argument of the ***panorays-finding-list*** command. The Panorays API uses cursor pagination, so the argument was never applied.
- Added the ***panorays-supplier-list*** command, which lists the suppliers in your Panorays portfolio.
- Added the ***panorays-supplier-finding-list*** command, which lists the findings detected for a specific supplier.
- Changed the default **Incidents Fetch Interval** to 15 minutes, which suits fetching across a supplier portfolio.
- When fetching supplier findings, a run that reaches **Maximum number of incidents to fetch per run** part-way through a supplier resumes on that same supplier, so the limit is honored and no findings are skipped.

#### Incident Types

##### New: Panorays Supplier Finding

- Added a new incident type for security findings detected by Panorays on your suppliers (third parties).

#### Incident Fields

- Added the following incident fields, which capture the supplier a finding belongs to:
  - **Panorays Supplier Name**
  - **Panorays Supplier ID**
  - **Panorays Supplier Domain**
  - **Panorays Supplier Business Impact**
  - **Panorays Supplier Combined Score**
  - **Panorays Supplier Posture Score**
  - **Panorays Supplier Risk**
  - **Panorays Supplier Tags**
- Associated the existing **Panorays Finding** incident fields with the new **Panorays Supplier Finding** incident type.
