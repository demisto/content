
#### Integrations

##### TrendAI Vision One™ Event Collector

- Fixed an issue where the ***fetch-events*** command's checkpoint for the *Observed Attack Techniques* and *Search Detections* log types could stop advancing correctly after a pagination token expired mid-backlog, causing the connector to repeatedly re-scan overlapping time windows and fall further behind real-time instead of catching up.
- Fixed an issue where the *Observed Attack Techniques* (`/v3.0/oat/detections`) requests used a `top` value of 1000, which is not a value accepted by the API (only 50, 100 or 200 are supported). The value is now clamped to a valid one, reducing the risk of request failures and gateway timeouts.
- Fixed an issue where the *Search Detections* (`/v3.0/search/detections`) requests' `top` value (derived from the fetch limit, which can be repeatedly halved by the fetch-timeout backoff logic) could end up being a value not accepted by the API (only 50, 100, 500, 1000 or 5000 are supported). The value is now clamped to a valid one.
- Added automatic retry with backoff for transient API failures (HTTP 502/500/503/504, connection drops and read timeouts) during ***fetch-events***, so short-lived Vision One outages no longer abort the whole fetch round and leave the checkpoint unpersisted.
- Fixed an issue where an error while fetching one log type (for example a *502 Bad Gateway* or a read timeout) would abort the entire ***fetch-events*** round and prevent any checkpoint from being saved, causing the connector to re-scan the same window on the next round. Each log type is now handled independently: a failing type keeps its checkpoint (so nothing is skipped) while the other types still fetch and advance normally.
- Improved memory usage and resilience by sending each log type to XSIAM and saving its checkpoint as soon as it is fetched, instead of accumulating all log types and sending them together at the end. Partial progress is now persisted even if another type fails.
- Improved diagnostics: added log entries covering fetch-limit origin, per-type fetch progress, timeout backoff, and the checkpoint decisions for the *Observed Attack Techniques* and *Search Detections* pagination chains, and reduced log noise from per-event deduplication detail.
