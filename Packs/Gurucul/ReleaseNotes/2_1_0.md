#### Integrations

##### Gurucul-GRA

- Added the *Fetch type* parameter (*Incidents* | *Alerts*). New imports use GRA Incidents or Alerts APIs; Cases are no longer fetched.
- Added the incident commands: ***gra-incidents***, ***gra-incident-action***, ***gra-incident-action-anomaly***, ***gra-incidents-anomaly***.
- Added the alert commands: ***gra-alerts***, ***gra-alert-get***, ***gra-alert-action***, ***gra-alert-update-history***.
- Added the thin War Room alert commands: ***gra-alert-comment***, ***gra-alert-assign***, ***gra-alert-in-progress***.
- Updated the ***gra-alert-action*** documentation for closeAlert *subStatus* enums (Incident: True Positive, Benign Positive, Policy Violation; Not An Incident: Model Review, Disable Model, False Positive).
- Updated the fetch behavior so Incident and Alert fetch use an ID cursor after the first bootstrap (*maxIncidentId* / *maxAlertId*). The time window from *First fetch time* is used only when no cursor exists yet.
- Updated the upgrade path so an existing *maxCaseId* last-run cursor is reused as *maxIncidentId* when the Incident cursor is missing (avoids re-bootstrapping with *First fetch time*).
- Set integration defaults for new instances: Mapper (incoming) *GRAIncident-Mapper* and Incident type *GRAIncident* (aligned with default *Fetch type* Incidents). Use a separate instance for Alerts with *GRAAlert-Mapper* and *GRAAlert*.
- Note: Before re-enabling fetch after updating to this version, disable the old Cases instance fetch, set *Fetch type* / Mapper / Incident type for *Incidents*, then re-enable. See the Gurucul-GRA integration README section *Upgrading from Case fetch (2.1.0)*. Existing ***gra-case-*** commands remain for already-imported GRACase incidents.
