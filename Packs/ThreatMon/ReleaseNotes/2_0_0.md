#### Integrations

##### ThreatMon Incident Management

- Updated the integration name to **ThreatMon Incident Management**. The integration ID and existing instances are not changed.
- Improved implementation of the fetch: changes are now followed by change time, so alarms that are approved later with an older alarm code, and alarms that move to a fetched status, are fetched as well. Each fetch reads a look-back window again and never creates an alarm twice. Existing instances continue from the last fetched alarm.
- Added the *First Fetch Time*, *Maximum number of incidents per fetch*, *Alarm Statuses to Fetch*, *Minimum Severity to Fetch*, *Alarm Categories to Fetch*, *Mask Secrets in Findings*, *Attach Screenshots*, *Look-back Window (minutes)*, *Source Reliability* and *Customer Name (MSSP)* parameters. With *Attach Screenshots*, the screenshots of the findings are attached to the incident.
- Added support for incoming and outgoing mirroring of the alarm status (Cortex XSOAR only), with the *Incident Mirroring Direction*, *Close Mirrored Cortex Incident* and *Close Mirrored ThreatMon Alarm* parameters.
- Added the following commands:
  - Alarms: ***threatmon-alarm-list***, ***threatmon-alarm-status-update*** (with an assignee and the people to inform), ***threatmon-alarm-stats***.
  - Response: ***threatmon-takedown-request*** and ***threatmon-data-removal-request***. ThreatMon's answers (not eligible, quota, not found, already requested) are returned as results, and the requests are never retried automatically.
  - Vulnerability Knowledge: ***cve***, ***threatmon-cve-get*** (with the AI report, the timeline and the mentions), ***threatmon-cve-search***, ***threatmon-cve-subscription-list*** and ***threatmon-subscribed-cve-search***.
  - Sandbox: ***threatmon-sandbox-file-submit*** (waits for the verdict), ***threatmon-sandbox-submission-list*** and ***threatmon-sandbox-result-get***. File verdicts are returned as file reputations.
  - Attack surface and posture: ***threatmon-asset-list***, ***threatmon-ciso-dashboard-get*** and ***threatmon-website-url-submit***.
  - Screenshots: ***threatmon-screenshot-get***.
  - MSSP: ***threatmon-customer-list***, ***threatmon-customer-create***, ***threatmon-customer-update***, ***threatmon-customer-delete***, ***threatmon-customer-keyword-add*** and ***threatmon-customer-keyword-remove***.
- Deprecated the ***threatmon_update_incident_status***, ***threatmon_request_takedown***, ***threatmon_request_data_removal***, ***threatmon_list_cves*** and ***threatmon_list_subscribed_cves*** commands. Use the new commands instead; ***threatmon-cve-search*** and ***threatmon-subscribed-cve-search*** replace the CVE list commands.
- Deprecated the *Fetch Interval (minutes)* parameter, which was not used. Use *Incidents Fetch Interval* instead.
- Note: **Changes for existing instances:**
  - Incidents are now named `ThreatMon #<alarm code>: <title>` (before: `Threatmon Alert: <title>`). Update playbooks or rules that match the old name.
  - Only alarms with the *Open* and *In Progress* statuses are fetched by default. To fetch every status as before, select all statuses in *Alarm Statuses to Fetch*.
  - Passwords, tokens and cookies in leak findings are masked by default. Clear *Mask Secrets in Findings* to keep the full values.
  - Alarms with the Information severity now get the Informational severity.
  - On an upgraded instance, alarms with an alarm code up to the last one that version 1.x fetched are not fetched again, even when ThreatMon approves them later. This prevents duplicates of the incidents that version 1.x created. New instances fetch late-approved alarms in every case.
  - To use the new incident type, layout and mirroring on an existing instance, set *Incident type* to **ThreatMon Alert**, *Mapper (incoming)* to **ThreatMon - Incoming Mapper** and *Mapper (outgoing)* to **ThreatMon - Outgoing Mapper**. New instances use them by default.
- Improved implementation of the error messages: they now explain a rejected API key, an IP address that is not whitelisted and an unknown MSSP customer name. Requests are retried when ThreatMon is rate limited or temporarily unavailable; takedown and data removal requests are never retried.
