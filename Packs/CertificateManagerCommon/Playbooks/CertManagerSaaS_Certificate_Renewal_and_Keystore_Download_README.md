# CertManagerSaaS Certificate Renewal and Keystore Download

Example playbook: renews a certificate with CyberArk Certificate Manager SaaS or Next-Gen Trust Security and downloads the new certificate with its private key and chain to the War Room. Adapt it before you use it in production.

The playbook stops before installing the certificate on a target. It does not deliver the certificate anywhere. To deliver it, replace the placeholder task "Install the certificate on your target" with the upload command of your target's integration.

The playbook does not run by itself: no issue type or automation rule starts it. Run it on an issue, or call it from your own playbook.

The private key passes through Cortex, encrypted with a passphrase. Set it in the integration instance's Keystore passphrase setting, from a saved credential; KeystorePassphrase overrides it for one run.

Prerequisites: a certificate whose key was generated by a VSatellite, and an issuing template whose key generation is done by a VSatellite.

## Playbook Inputs

| Name | Description | Default Value | Required |
| --- | --- | --- | --- |
| CertificateFingerprint | The SHA-1 fingerprint of the certificate to renew. Defaults to the fingerprint mapped onto a fetched issue. | `${incident.certmanagersaasfingerprint}` | Optional |
| KeystoreFormat | The keystore format: PKCS12 \(one .p12 file\) or PEM \(an encrypted private key file and a chain file, leaf first\). Pick the format your target accepts. | PKCS12 | Optional |
| KeystorePassphrase | The passphrase that encrypts the downloaded private key. Leave it empty to use the integration instance's Keystore passphrase setting, which can come from a saved credential (recommended). Don't type the passphrase here or save it as a default value. |  | Optional |
| ApplicationID | The identifier of the Certificate Manager SaaS application the renewed certificate is requested for. Required for Certificate Manager SaaS; not used by Next-Gen Trust Security. |  | Optional |
| CertificateIssuingTemplateID | The identifier of the issuing template the renewed certificate is issued under. Its key generation must be done by a VSatellite, or the private key cannot be downloaded. |  | Required |
| ValidityPeriod | The requested validity of the renewed certificate, as an ISO 8601 duration. Leave empty to use the issuing template default. |  | Optional |

## An example that stops before the install

This playbook shows the first half of certificate delivery: it gets a renewed certificate and its
private key from Certificate Manager SaaS or Next-Gen Trust Security into Cortex. **It does not
install the certificate on a target.** The task "Install the certificate on your target
(placeholder)" marks where the install step goes; as shipped, it does nothing.

To deliver the certificate, copy the playbook and replace the placeholder with the upload command
of your target's integration, for example a web application firewall, a load balancer or a key
vault. Pass it the War Room files and `KeystorePassphrase`:

- **PKCS12:** `CertManagerSaaS.Keystore.KeystoreFileName`, one `.p12` file with the key and the
  chain.
- **PEM:** `CertManagerSaaS.Keystore.PrivateKeyFileName` (the encrypted private key) and
  `CertManagerSaaS.Keystore.ChainFileName` (the chain, leaf first).

It doesn't run by itself. It isn't bound to an issue type, and the pack ships no automation rule
for it. On XSIAM, adopt it in the Playbook Catalog before you run it.

## What this playbook does

1. Resolve the certificate by fingerprint in every enabled integration. Continue only when exactly
   one certificate matched.
2. Renew it with the **CertManagerSaaS Certificate Request** sub-playbook: same common name and
   subject alternative names, linked to the old certificate, through the integration and instance
   that hold it. The sub-playbook also downloads the new certificate's keystore in
   `KeystoreFormat`, encrypted with `KeystorePassphrase`.
3. Reach the install placeholder only when the keystore was downloaded.
4. Write a summary on the case: the renewal and the downloaded files, with a clear statement that
   nothing was installed, or why it failed (no single certificate, renewal failed, or keystore
   download failed, with the reason).

## Security

The private key leaves the certificate service and passes through Cortex. Read this before you
use the playbook.

- **The key is always encrypted.** The service encrypts it with the passphrase. The files
  stay in the War Room after the run, so anyone who can read the case and knows the passphrase can
  use the key.
- **Keep the passphrase out of the playbook.** Set it in the integration instance's **Keystore
  passphrase** setting, from a saved credential, and leave `KeystorePassphrase` empty. A task's inputs are visible in the work plan, so limit who can
  see the case.
- **Check your install step.** The integration you add for the install receives the key and the
  passphrase. Check how it sends them and whether it shows them in the War Room.

## Prerequisites

- **The key was generated by a VSatellite.** Only such keys can be exported. Use an issuing
  template whose key generation is done by a VSatellite.
