#### Integrations

##### Reco
- Note: The ***fetch-incidents*** *Risk level* parameter now fetches alerts at the given severity and above, instead of an exact match. For example, setting it to *MEDIUM* now also returns *HIGH* and *CRITICAL* alerts.
- Updated the alert fetching, identity, app, file, and label commands to use the new Reco External API for cleaner JSON responses and improved reliability. All pre-migration output field names are still populated alongside the new ones for backward compatibility. A few fields have no equivalent in the new External API and are no longer populated: ***reco-get-user-context-by-email-address*** *Reco.User.groups* and *Reco.User.labels*; ***reco-get-sensitive-assets-by-id***, ***reco-get-sensitive-assets-by-name***, and ***reco-get-assets-by-id*** *Reco.SensitiveAssets.currently_permitted_users* and *source*; ***reco-get-apps*** *Reco.Apps.risk_score*, *status*, and *updated_at*; ***reco-set-app-authorization-status*** *Reco.AppAuthorization.rows_affected*.
- Added support for rate-limit handling (automatic 429 retry with exponential backoff) for all External API calls.
- Added the following commands, all backed by the External API and accepting SCIM v2 filter expressions: ***reco-list-events***, ***reco-list-posture-issues***, ***reco-list-accounts***, ***reco-list-devices***, ***reco-list-ai-agents***, ***reco-list-groups***, ***reco-list-saas-to-saas***, ***reco-list-ip-addresses***, ***reco-list-business-units***, ***reco-list-audit-logs***, ***reco-list-posture-checks***, ***reco-list-threat-detection-policies***, ***reco-list-exclusions***, and ***reco-list-app-instances***.
- Added the full set of valid *status* values to ***reco-change-alert-status*** (previously only 3 of the 12 supported statuses were listed).
