#### Integrations

##### Reco

- Added source-side alert filtering to ***fetch-incidents***. The following parameters are sent to the Reco API, so unwanted alerts are never ingested into Cortex: *SaaS application/platform*, *Alert status*, *Include labels*, *Exclude labels*, and *Advanced filter (SCIM)*. The advanced filter supports AND, OR, and NOT logic and any other alert field the Reco API can filter on. The existing *Source* and *Minimum risk level* parameters are unchanged.
- Added the ***reco-list-alerts*** command to list alerts for a specified time range and filters (platform, risk level, labels, status, source, and a SCIM expression). It does not use or change the fetch-incidents configuration or last-run timestamp.
- Added the ***reco-get-alert*** command to retrieve a single alert, including its policy violations, by ID.
- Added the ***reco-fetch-alerts*** command to retrieve detailed alerts for a historical time range and filters, for investigations, mapping tests, and controlled backfills. It returns the alerts to the context only; it does not create incidents or change the fetch-incidents last-run timestamp.
- Fixed an issue where the *Before* parameter caused ***fetch-incidents*** to fail and the *After* parameter was ignored. Both are now applied, and an unparsable value is reported as an error.
- Improved the ***Test*** button so it sends exactly the same filters as ***fetch-incidents***, including the new ones.
