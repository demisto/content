#### Integrations

##### KELA Identity Guard

- Fixed **fetch-incidents** creating duplicate incidents. The KELA API treats
  the ``createdDate`` ``startDate`` filter as inclusive, so the record sitting
  exactly at the last-run timestamp was returned, and re-created in Cortex XSOAR,
  on every fetch cycle. The integration now remembers, per source, the IDs of the
  records at the last-run timestamp and skips them on the next cycle.
- Records filtered out by **Minimum severity to fetch** now also advance the
  last-run timestamp, so they are no longer re-read on every cycle.
- Upgrading from 1.0.1 needs no manual reset: the existing last run is migrated
  automatically and does not re-create the already ingested records.
