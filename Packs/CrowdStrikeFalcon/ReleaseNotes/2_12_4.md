
#### Integrations

##### CrowdStrike Falcon

- Fixed an issue where the Spotlight vulnerabilities assets snapshot never sealed because records were counted before the asynchronous send to XSIAM, so failed sends were counted-but-dropped (declared > stored). Records are now counted only after XSIAM confirms storing them, counting each batch by the number of records actually stored. A failed send no longer aborts the severity: the fetch continues with the remaining pages and the records that were not stored are simply not counted, and are picked up on the next fetch cycle.
- Fixed an issue where a page with no records left to send could still be sent to XSIAM and counted as one record that did not exist, causing the snapshot to declare more records than were stored.
- Fixed an issue where a cancelled background send could abort an entire severity fetch instead of being skipped like any other failed send.
- Fixed an issue where oversized vulnerability pages could be truncated and raise a JSON decode error that aborted an entire severity fetch. The same page is now retried with progressively smaller page sizes and automatically reverts to the default size on the next page.
- Added the *Long running instance for Spotlight vulnerabilities* parameter, which runs the Spotlight vulnerabilities fetch in a long-running container instead of on the assets fetch schedule. Use it when a full Spotlight fetch takes longer than the assets fetch interval and is therefore repeatedly interrupted. A fetch cycle starts every 24 hours, and each cycle runs to completion before the next one starts, so a fetch may take any amount of time, including more than 24 hours. When this option is enabled, do not also enable the assets fetch. This mode fetches Spotlight vulnerabilities only; CNAPP Alerts continue to be ingested only by the regular assets fetch.
