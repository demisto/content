
#### Integrations

##### CrowdStrike Falcon

- Fixed an issue where Spotlight assets were never collected on tenants that span multiple CIDs (CrowdStrike Flight Control / MSSP parent-child deployments). On such tenants Spotlight returns the CID and the device ID joined together, which the CrowdStrike Devices API rejects. The device ID is now extracted before the request is sent. Vulnerability collection was not affected.
- Fixed an issue where the Spotlight vulnerabilities assets snapshot never sealed because records were counted before being sent to Cortex XSIAM, so failed sends were counted but never stored. Records are now counted only after Cortex XSIAM confirms storing them, and a failed send no longer aborts the severity - the remaining pages are still fetched, and the records that were not stored are picked up on the next fetch cycle.
- Fixed an issue where an empty page could be sent to Cortex XSIAM and counted as a record that did not exist, causing the snapshot to declare more records than were stored.
- Fixed an issue where a cancelled background send could abort an entire severity fetch instead of being skipped like any other failed send.
- Fixed an issue where an HTTP error returned by Cortex XSIAM while sending a batch (for example, *Bad Gateway*) was logged but ignored, so the batch was counted as stored and the snapshot never sealed. A rejected batch is now treated as a failed send and its records are not counted.
- Fixed an issue where oversized vulnerability pages could be truncated and raise a JSON decode error that aborted an entire severity fetch. The page is now retried with progressively smaller page sizes and reverts to the default size on the next page.
- Fixed an issue where a transient CrowdStrike service error that exhausted the API client's retries aborted an entire severity fetch. The page is now retried, so a temporary upstream outage no longer prevents the snapshot from sealing.
- Added the *Long running instance for Spotlight vulnerabilities* parameter, which runs the Spotlight vulnerabilities fetch in a long-running container instead of on the assets fetch schedule. Use it when a full Spotlight fetch takes longer than the assets fetch interval and is therefore repeatedly interrupted. A cycle starts every 24 hours and always runs to completion first, so a fetch may take longer than 24 hours. A failed cycle is retried after a short delay that grows with each consecutive failure. When this option is enabled, do not also enable the assets fetch on the same instance. This mode fetches Spotlight vulnerabilities only; to collect CNAPP Alerts, configure a separate instance using the regular assets fetch.
