
#### Integrations

##### CrowdStrike Falcon

- Fixed an issue where Spotlight assets were never collected on tenants that span multiple CIDs (CrowdStrike Flight Control / MSSP parent-child deployments). On such tenants Spotlight returns the CID and the device ID joined together, which the CrowdStrike Devices API rejects. The device ID is now extracted before the request is sent. Vulnerability collection was not affected.
- Fixed an issue where the Spotlight vulnerabilities assets snapshot never sealed because the declared record count did not match what was actually stored in Cortex XSIAM. Records were counted before being sent, an HTTP error returned while sending a batch (for example, *Bad Gateway*) was logged but otherwise ignored, and an empty page was counted as a record that did not exist. Records are now counted only after Cortex XSIAM confirms storing them, a rejected batch is treated as a failed send, and empty pages are no longer sent.
- Fixed an issue where a single failure aborted an entire severity fetch, so all remaining pages of that severity were lost. A failed or cancelled background send is now skipped like any other failed send, the remaining pages are still fetched, and the records that were not stored are picked up on the next fetch cycle.
- Fixed an issue where a page that could not be fetched aborted an entire severity fetch, either because an oversized page was truncated and raised a JSON decode error, or because a transient CrowdStrike service error exhausted the API client's retries. The same page is now retried with progressively smaller page sizes and reverts to the default size on the next page, so a temporary upstream fault no longer prevents the snapshot from sealing.
- Fixed an issue where a transient Cortex XSIAM error while sending a batch (for example, *Bad Gateway*) marked the instance as errored even when a retry succeeded and no data was lost, and reported the reason twice in the error message. The error is now reported only after all retry attempts fail. Retries were also sent immediately one after another, so a brief error outlasted all of them; the integration now waits between attempts.
- Added the *Long running instance for Spotlight vulnerabilities* parameter, which runs the Spotlight vulnerabilities fetch in a long-running container instead of on the assets fetch schedule. Use it when a full Spotlight fetch takes longer than the assets fetch interval and is therefore repeatedly interrupted. A cycle starts every 24 hours and always runs to completion first, so a fetch may take longer than 24 hours. A failed cycle is retried after a short delay that grows with each consecutive failure.
NOTE: When this option is enabled, do not also enable the assets fetch on the same instance. This mode fetches Spotlight vulnerabilities only; to collect CNAPP Alerts, configure a separate instance using the regular assets fetch.
