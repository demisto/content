#### Integrations

##### Palo Alto Networks Enterprise DLP

- Updated the incident fetch to use the v4 incident inventory API instead of the deprecated v1 incident notifications API. Incident fields are mapped internally, so no mapper or layout changes are required.
- All configured regions are now covered by a single query, fixing incidents being skipped when the fetch limit was reached before every region was queried.
- Fixed an issue where a customized **Server URL** caused the fetch to silently return no incidents.
- Fixed an issue where an incident with a missing or malformed creation timestamp caused the entire fetch to fail.
- Fixed an issue where a failed or incomplete incident query advanced the fetch time window, causing incidents in that window to be skipped.
- Added the **DLP Channels**, **DLP Severities**, **DLP Incident Statuses**, **DLP Priorities**, **DLP Data Profile IDs**, **DLP Data Pattern IDs**, **DLP Incident Tags**, **DLP Report IDs**, **DLP URL Domains**, **DLP Assets**, **DLP Actions**, **DLP Policy Types** and **DLP Sub Policy Types** parameters, to narrow the incidents fetched. All the configured filters are combined, so an incident is fetched only if it matches every one of them.
- The **DLP Channels**, **DLP Severities**, **DLP Incident Statuses**, **DLP Priorities**, **DLP Actions** and **DLP Policy Types** values are selected from the list of values the incidents carry. The selected severity is translated before the query is sent, since the severity is stored as a number - *Critical* becomes *5* and *Informational* becomes *1*.
- Fixed an issue where the *AP*, *PAR* and *SUI* options of the **DLP Regions** parameter matched no incidents. The options are now *SG*, *FR* and *CH*, and instances configured with the previous values keep fetching.
- Added the *SA* option to the **DLP Regions** parameter.
- Fixed an issue where the **App** incident field was empty on incidents fetched from the v4 API. The field is populated again from the application the control point resolved.
- Fixed an issue where a failed or incomplete request for a later page of incidents advanced the fetch time window, causing the incidents on the unread pages to be skipped.
- Fixed an issue where incidents fetched from the v4 API were assigned a severity one level higher than in DLP, and *Critical* incidents an invalid severity. The DLP severity is now translated to the matching XSOAR severity.
- Updated the documentation to state that incidents are fetched from every control point, and that the **DLP Channels** parameter narrows the fetch.
- Updated the Docker image to: *demisto/python3:3.12.14.13495286*.
