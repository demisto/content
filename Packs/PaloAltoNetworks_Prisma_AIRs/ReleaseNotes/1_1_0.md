#### Playbooks

##### New: PaloAltoNetworks_Prisma_AIRs_AI_Gateway_API_Key_Expiration_Check

Created a new playbook that checks the expiration dates of the AI Gateway API keys (both service and user keys, across every workspace) for an integration instance. It lists the workspaces, enumerates the service and user API keys in each, and keeps the active keys that have an expiry set (keys with no expiry are out of scope). Each remaining key is bucketed into low/medium/high/critical risk by how many days remain until expiration, using tunable day-threshold inputs (*CriticalWithinDays*, *HighWithinDays*, *MediumWithinDays*) so the ranges can be adjusted per use case. The keys are grouped by severity in context and written to the War Room as one table per severity, ordered most severe to least severe. An email is sent when at least one key is more than medium risk (**Critical** or **High**) and at least one recipient is configured, listing the offending keys grouped by severity (critical first). When no key is **Critical** or **High** the incident is closed automatically; otherwise the playbook pauses on a manual "approve to close" task so the keys can be rotated before the incident is closed. The playbook pins every command to the instance named in the *InstanceName* input, so it can be cloned per tenant.

##### New: PaloAltoNetworks_Prisma_AIRs_AI_Gateway_Status_Check

Created a new playbook that checks the health of the configured AI Gateway deployments for an integration instance (using the *connection_status* of each deployment). When all gateways are healthy (or none are configured) the incident is closed automatically. When one or more gateways are unhealthy, the offenders are written to the War Room as a human-readable table, an email notification is sent when notifications are enabled and at least one recipient is configured, and the playbook pauses on a manual "approve to close" task so the problem can be validated before the incident is closed. The playbook pins every command to the instance named in the *InstanceName* input, so it can be cloned per tenant.

##### New: PaloAltoNetworks_Prisma_AIRs_Red_Team_Network_Channel_Status_Check

Created a new playbook that checks the health of the Red Team network broker channels for an integration instance. It flags offline channels (status **OFFLINE**; **DRAFT**/not-yet-completed channels are informational) and online channels whose connected clients are running an outdated version (using the *outdated_clients_count* and *oldest_client_version* of each channel against the current *client_version* from the stats command). Offenders are written to the War Room as human-readable tables (the outdated table is titled with the version to upgrade to), and email notifications are sent when at least one recipient is configured. Each check is independently gated by the *NotifyOffline* and *NotifyOutdated* inputs so you can tune what the playbook investigates and alerts on. When nothing needs remediation the incident is closed automatically; when a problem is found the playbook pauses on a manual "approve to close" task so it can be validated before the incident is closed. The playbook pins every command to the instance named in the *InstanceName* input, so it can be cloned per tenant.
