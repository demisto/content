#### Integrations

##### New: Palo Alto Networks Prisma AIRS - AI Gateway

- New integration for managing Prisma AIRS AI Gateway governance resources, including guardrails and organization guardrails, gateway configs and versions, deployments, rate- and usage-limit policies, secret references, and MCP servers and integrations. Authenticates with a dedicated AI Gateway API key (bearer token).

#### Playbooks

##### New: Palo Alto Networks Prisma AIRS - AI Gateway Status Check

- New playbook that checks the health of the configured AI Gateway deployments for an integration instance (using each deployment's connection_status). When all gateways are healthy (or none are configured) the incident is closed automatically. When one or more gateways are unhealthy, the offenders are written to the War Room as a human-readable table, an email notification is sent when notifications are enabled and at least one recipient is configured, and the playbook pauses on a manual "approve to close" task so the problem can be validated before the incident is closed. Pins every command to the instance named in the InstanceName input, so it can be cloned per tenant.

##### New: Palo Alto Networks Prisma AIRS - Red Team Network Channel Status Check

- New playbook that checks the health of the Red Team network broker channels for an integration instance. It flags offline channels (status OFFLINE; DRAFT/not-yet-completed channels are informational) and online channels whose connected clients are running an outdated version (using each channel's outdated_clients_count and oldest_client_version against the current client_version from the stats command). Offenders are written to the War Room as human-readable tables (the outdated table is titled with the version to upgrade to), and email notifications are sent when at least one recipient is configured. Each check is independently gated by the NotifyOffline and NotifyOutdated inputs so you can tune what the playbook investigates and alerts on. When nothing needs remediation the incident is closed automatically; when a problem is found the playbook pauses on a manual "approve to close" task so it can be validated before the incident is closed. Pins every command to the instance named in the InstanceName input, so it can be cloned per tenant.
