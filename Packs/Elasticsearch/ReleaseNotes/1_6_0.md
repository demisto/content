
#### Classifiers

##### New: Elasticsearch

- New: Added a new **Elasticsearch** classifier that classifies Elasticsearch entities using the deterministic `elastic_entity_kind` field set by the integration on every fetched incident: `signal` is classified as Elasticsearch Security Alert, `securitySolution` is classified as Elasticsearch Case, and any other value falls back to the default Elasticsearch incident type.

#### Incident Fields

##### New: Elasticsearch Case Close Reason

- New: Added a new **Elasticsearch Case Close Reason** incident field that stores the reason an Elasticsearch case was closed, used when mirroring the case closure to and from Cortex XSOAR.

##### New: Elasticsearch Case ID

- New: Added a new **Elasticsearch Case ID** incident field that stores the unique identifier of the Elasticsearch case, used to correlate and mirror the case with its Cortex XSOAR incident.

##### New: Elasticsearch Workflow Alert Status Reason

- New: Added a new **Elasticsearch Workflow Alert Status Reason** incident field that stores the workflow reason (`kibana.alert.workflow_reason`) of an Elasticsearch security alert, indicating why its workflow status was set.

##### New: Elasticsearch Case Status

- New: Added a new **Elasticsearch Case Status** incident field that stores the current status of the Elasticsearch case (for example, open, in-progress, or closed).

##### New: Elasticsearch Alert ID

- New: Added a new **Elasticsearch Alert ID** incident field that stores the unique identifier (`kibana.alert.uuid`) of the Elasticsearch security alert, used to correlate and mirror the alert with its Cortex XSOAR incident.

##### New: Elasticsearch Workflow Alert Status

- New: Added a new **Elasticsearch Workflow Alert Status** incident field that stores the workflow status (`kibana.alert.workflow_status`) of an Elasticsearch security alert, such as open, acknowledged, or closed.

##### New: Elasticsearch Alert Reason

- New: Added a new **Elasticsearch Alert Reason** incident field that stores the reason (`kibana.alert.reason`) generated for the Elasticsearch security alert, describing why the alert was triggered.

##### New: Elasticsearch Status Update Date

- New: Added a new **Elasticsearch Status Update Date** incident field that stores the date and time (`kibana.alert.workflow_status_updated_at`) when the workflow status of the Elasticsearch security alert was last updated.

#### Incident Types

##### New: Elasticsearch Security Alert

- New: Added a new **Elasticsearch Security Alert** incident type that represents a security alert fetched from Elasticsearch, enabling dedicated layouts, mappers, and mirroring for Elasticsearch security alerts.
<~XSOAR> (Available from Cortex XSOAR 6.2.0).</~XSOAR>

##### New: Elasticsearch Case

- New: Added a new **Elasticsearch Case** incident type that represents a case fetched from Elasticsearch, enabling dedicated layouts, mappers, and mirroring for Elasticsearch cases.

#### Integrations

##### Elasticsearch v2

- Added support for the **Fetch incident types** parameter that sets the type of incident to fetch from Elasticsearch (security alert, case, or other entity).
- Added support for the **Incident Mirroring Direction** parameter. Mirroring works only for the Elasticsearch Security Alert and Elasticsearch Case incident types.
- Added support for the **Fetch alerts for case** parameter that, when enabled, fetches alerts associated with each Elasticsearch case. You must have read privileges for the Cases feature in the Management, Observability, or Security section of the Kibana feature privileges.
- Added support for the **Fetch cases by Severity** parameter that sets the case severities to fetch. If none is chosen, all severity levels will be returned. Relevant only for the Elasticsearch Case incident type.
- Added support for the **Fetch cases by Status** parameter that sets the case statuses to fetch. If none is chosen, in-progress and open will be returned. Relevant only for the Elasticsearch Case incident type.
- Added support for the **Close Mirrored XSOAR Incident** parameter that, when selected, mirrors closing the Elasticsearch alert or case in Cortex XSOAR.
- Added support for the **Close Mirrored Elasticsearch Incident** parameter that, when selected, mirrors closing the Cortex XSOAR incident in Elasticsearch.
- Added support for the **get-remote-data** command that gets the remote data of a specific incident. This command is used for mirroring in and should be used for debugging purposes.
- Added support for the **get-modified-remote-data** command that gets the list of incidents that were modified since the last update time. This command is used for mirroring in and should be used for debugging purposes.
- Added support for the **update-remote-system** command that updates the remote system with local incident changes. This command is used for mirroring out and should be used for debugging purposes.

#### Mappers

##### New: Elasticsearch Case - Incoming Mapper

- New: Added a new **Elasticsearch Case - Incoming Mapper** that maps incoming Elasticsearch Case fields to Cortex XSOAR incident fields.

##### New: Elasticsearch Case - Outgoing Mapper

- New: Added a new **Elasticsearch Case - Outgoing Mapper** that maps Cortex XSOAR incident fields to outgoing Elasticsearch Case fields.

##### New: Elasticsearch Security Alert - Incoming Mapper

- New: Added a new **Elasticsearch Security Alert - Incoming Mapper** that maps incoming Elasticsearch Security Alert fields to Cortex XSOAR incident fields.

##### New: Elasticsearch Security Alert - Outgoing Mapper

- New: Added a new **Elasticsearch Security Alert - Outgoing Mapper** that maps Cortex XSOAR incident fields to outgoing Elasticsearch Security Alert fields.
