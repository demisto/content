
#### Integrations

##### Abnormal Security

- Fixed an issue where incidents could be missed when a fetch run reached the *Maximum incidents to fetch* limit. Each incident type now resumes from where the previous run stopped.
- Fixed an issue where a single failing threat, abuse campaign or case could stop the whole fetch run. Failing items are retried on the next runs and skipped with a warning in the instance's health after failing on 3 runs.
- Added support for creating one incident per Account Takeover case, instead of a new incident each time a case is modified, resolved or reopened. To use it, set *Case fetch mode* to *Created time*.
- Improved implementation of ***fetch-incidents***. Incident details are now retrieved concurrently, within a configurable request rate that stays well under the API's rate limit.
- Improved implementation of ***fetch-incidents***. Each run now stops within a configurable time budget and saves its progress, so it finishes before the fetch timeout.
- Added the *Case fetch mode*, *Fetch time budget (in seconds)*, *Maximum fetch window (in minutes)*, *Concurrent detail requests* and *Maximum requests per second* parameters. *Case fetch mode* defaults to *Last modified time*, which keeps the current Account Takeover case behavior.
- Updated the integration to use **ContentClient** for its API calls.
- Updated the Docker image to: *demisto/fastapi:0.125.0.12689358*.
