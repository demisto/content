
#### Integrations

##### Keeper Security

- **Breaking change:** The integration now collects audit events from the Keeper Admin REST API (`/api/rest/public/events`) and authenticates with an **API key** (scope `SIEM:1`) instead of a username, password and Keeper Commander device registration. Update the instance configuration with a new API key.
- Removed the `keeper-security-register-start`, `keeper-security-register-complete` and `keeper-security-register-test` commands.
- Added the `keeper-security-get-events` command and the **First fetch time** parameter.
- Updated the Docker image to: *demisto/python3*.

#### Modeling Rules

##### Keeper Security Modeling Rule

- Updated the mapping to the fields returned by the Admin REST API (`audit_event`, `remote_address`, `category`, `client_version`, `enterprise_id`, `username`, `timestamp`). Fields that the API does not return (for example record, team or node identifiers, and result codes) are no longer mapped.
