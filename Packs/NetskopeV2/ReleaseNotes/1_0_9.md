#### Integrations

##### Netskope - Direct to Zero Trust

- Added REST API v1 authentication for file hash list updates by sending the dedicated v1 token as the required query parameter.

- Added device tag and device classification commands (beta Device Classification API):
  - ***netskopev2-list-device-classification-tags***
  - ***netskopev2-create-device-classification-tag***
  - ***netskopev2-create-device-classification-rule***
  - ***netskopev2-find-device***
  - ***netskopev2-create-device-tag***
  - ***netskopev2-list-device-tags***
  - ***netskopev2-apply-device-tags***
- Added Destination Profile and Network Profile commands:
  - ***netskopev2-list-destination-profiles***
  - ***netskopev2-create-destination-profile***
  - ***netskopev2-get-destination-profile***
  - ***netskopev2-update-destination-profile***
  - ***netskopev2-update-destination-profile-values***
  - ***netskopev2-delete-destination-profile***
  - ***netskopev2-deploy-destination-profiles***
  - ***netskopev2-revert-destination-profile***
  - ***netskopev2-get-destination-profile-applied-version***
  - ***netskopev2-migrate-url-list-to-destination-profile***
  - ***netskopev2-migrate-url-list-into-destination-profile***
  - ***netskopev2-list-network-profiles***
  - ***netskopev2-create-network-profile***
  - ***netskopev2-get-network-profile***
  - ***netskopev2-update-network-profile***
  - ***netskopev2-update-network-profile-values***
  - ***netskopev2-delete-network-profile***
  - ***netskopev2-deploy-network-profiles***
  - ***netskopev2-revert-network-profile***
  - ***netskopev2-get-network-profile-applied-version***
- Added private application (ZTNA/NPA) commands: ***netskopev2-create-private-app***,
  ***netskopev2-update-private-app***, ***netskopev2-delete-private-app***,
  ***netskopev2-list-private-apps***, ***netskopev2-list-publishers***.
- Added a new command, ***netskopev2-replace-private-app***, which fully replaces an existing
  private application via the API's PUT endpoint. Unlike ***netskopev2-update-private-app*** (a
  PATCH - only the fields you provide are changed), this is a full-resource replace: host,
  protocols, and publishers must all be provided, and any other field left out may be cleared
  rather than left unchanged.
- Added a new command, ***netskopev2-url-lookup***, which bulk looks up URL categorization and
  reputation info (up to 100 URLs per call) - returns matched categories, associated app, dynamic
  classification, resolved IP, and any matching custom URL lists. This is a licensed feature on
  the Netskope side; Netskope returns an error if URL Lookup isn't enabled for the tenant.
- Fixed ***netskopev2-add-url*** and ***netskopev2-remove-url*** dumping the entire URL list
  content (which can be very large) into the War Room readable output, sometimes triggering
  "entry too big to display" truncation. The full list is still available in context - only the
  human-readable summary was changed to show a compact confirmation (added/removed URLs, total
  count, type, pending status) instead of every URL in the list.
- ***netskopev2-update-file-hash-list*** now validates that every hash is a valid MD5 (32 hex
  characters) or SHA256 (64 hex characters) before sending the request, and strips blank entries
  (e.g. from joining an empty "existing hashes" value with a comma) so they don't get rejected as
  invalid.
- Fixed ***netskopev2-update-file-hash-list*** sometimes failing with a client-side read timeout
  even though the update succeeded on the Netskope side - this endpoint can take longer to
  respond than the default timeout. Extended to 125 seconds, matching the same fix already
  applied to the destination/network profile deploy endpoints.
- ***netskopev2-update-file-hash-list*** now treats a "duplicate request, no change" response as
  success rather than an error. This response means the desired state (the given hashes already
  being in the list) is already true - for this idempotent, replace-style operation that's not a
  failure, and treating it as one was breaking playbooks that re-run with an unchanged hash set
  (e.g. after a prior client-side timeout whose request had actually already succeeded).
- ***netskopev2-update-destination-profile-values*** and
  ***netskopev2-update-network-profile-values*** now use an extended (125s) timeout. The values
  endpoint can take longer than the default timeout to respond even though the update itself
  succeeds server-side; without the extended timeout, a client-side timeout on this call led to a
  retry against an append/remove operation that has no server-side dedup, silently double-applying
  the value.
- ***netskopev2-create-destination-profile*** and ***netskopev2-update-destination-profile***
  (and their network profile equivalents) now accept the ***type*** argument case-insensitively.
  Previously "Regex" or "REGEX" was rejected even though it matches one of the valid values
  ("regex", "sensitive", "insensitive") except for case - a natural mistake to make since the
  Netskope UI itself displays the choice as "RegEx".
- ***netskopev2-submit-file-scan*** now rejects unsupported file types before making an API call,
  per the sandbox scan API's own constraints: only zip, exe, pdf, doc, xls, ppt, and rtf files are
  accepted (the file should be a password-protected .zip whose one member is
  exe/pdf/doc/xls/ppt/rtf, though a plain .zip is also accepted directly).
- Fixed ***netskopev2-create-private-app*** and ***netskopev2-update-private-app*** incorrectly
  rejecting an empty ***protocols*** or ***publishers*** argument as invalid JSON. Playbooks
  commonly pass an explicit empty string for an unfilled optional argument rather than omitting
  it entirely - this is now treated the same as not providing the argument, matching
  ***netskopev2-update-private-app***'s "only fields provided are changed" behavior.
- ***netskopev2-list-publishers*** now accepts an optional ***fields*** argument to restrict
  which fields are returned, matching the same capability already available on the underlying
  API. Recommended when a publisher has many connected app segments - the full unrestricted
  response can be large enough that XSOAR strips it from context and attaches it as a file
  instead, which was silently breaking any downstream logic that reads the list from context.
- Fixed ***netskopev2-create-private-app*** and ***netskopev2-update-private-app*** silently
  creating/changing nothing when ***protocols*** or ***publishers*** was passed a bare JSON
  scalar (e.g. ***protocols="443"***) instead of the expected array of objects. A bare number or
  string is valid JSON on its own, so the existing "must be valid JSON" check didn't catch it;
  both arguments now validate the parsed value is actually a JSON array of objects and raise a
  clear error otherwise.

#### Scripts

##### New: NetskopeBuildProtocolsJson

Builds the JSON array ***netskopev2-create-private-app***/***netskopev2-update-private-app***
expect for their `protocols` argument from a plain comma-separated port list.

##### New: NetskopeResolvePrivateAppId

Resolves a private app (ZTNA/NPA) ID from a name, since ***netskopev2-list-private-apps*** has no
name filter argument.

##### New: NetskopeResolvePublishers

Resolves comma-separated publisher names to the JSON array
***netskopev2-create-private-app***/***netskopev2-update-private-app*** expect for their
`publishers` argument, since ***netskopev2-list-publishers*** has no name filter argument.

##### New: NetskopeMergePrivateAppFields

Fetches a private app's current host/protocols/tags and applies add/remove deltas, so the Manage
Private App Segment playbook's modify flow can add or remove individual values without replacing
the whole field (***netskopev2-update-private-app*** is a full-field PATCH, not a merge).

##### New: NetskopeIndicatorSync

Searches XSOAR Threat Intel for Domain/URL/IP/CIDR indicators and syncs new values into a Netskope
Destination Profile.

##### New: NetskopeFileHashSync

Searches XSOAR Threat Intel for File indicators and extracts valid MD5/SHA256 hashes to sync into
a Netskope file hash list.

##### New: NetskopeFileScanLabels

Builds incident labels from a ***netskopev2-get-scan-report*** result.

##### New: NetskopeURLLookupLabels

Builds incident labels from a ***netskopev2-url-lookup*** result.

##### New: NetskopeGetXsoarListContent

Reads (and creates if missing) an XSOAR List by name, used to track Netskope file hash list
content between playbook runs.

##### New: NetskopeSetXsoarListContentWithRetry

Writes to an XSOAR List with retry on a transient version-conflict error, used to track Netskope
file hash list content between playbook runs.

#### Playbooks

##### New: Block Domain - Netskope

Blocks a domain by adding it to an existing Netskope URL List.

##### New: Block Domain - Destination Profile - Netskope

Blocks a domain via a Netskope Destination Profile, creating the profile if it doesn't exist yet.

##### New: Block IP - Network Profile - Netskope

Blocks an IP address, IP range, or CIDR netmask via a Netskope Network Profile.

##### New: Manage Private App Segment - Netskope

Creates, modifies, or deletes a Netskope private application (ZTNA/NPA) segment.

##### New: Sync Threat Intel to Destination Profile - Netskope

Scheduled playbook that keeps a Netskope Destination Profile in sync with indicators already
ingested into XSOAR's Threat Intel Management.

##### New: Sync Threat Intel to File Hash List - Netskope

Scheduled playbook that keeps a Netskope file hash list in sync with File indicators already
ingested into XSOAR's Threat Intel Management.

##### New: Threat Inspection - Netskope

Submits a file for Netskope's sandbox scan and polls for the result.

##### New: Update File Hash List - Netskope

Adds hashes to a Netskope file hash list, tracking the running set on the XSOAR side since
Netskope's v1 API has no read-back endpoint.

##### New: URL Lookup - Netskope

Looks up a URL's categorization/reputation info and records the result as labels on the incident.
