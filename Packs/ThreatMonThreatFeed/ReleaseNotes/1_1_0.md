
#### Integrations

##### ThreatMon Threat Feed

- Fixed an issue where only the first fetch ingested indicators. Subsequent fetches skipped every IOC that was re-observed by ThreatMon, because the checkpoint was based on the IOC creation time.
- Improved implementation to fetch from the ThreatMon TAXII 2.1 server with full cursor pagination instead of the daily IOC API, which returned at most 1,000 indicators per request.
- Added the *Collections*, *First Fetch Time*, *Look-back Window (minutes)* and *Maximum pages per fetch* parameters. Large fetches resume from the last saved page in the next run.
- Improved implementation so that a collection that cannot be fetched no longer blocks the other collections. The failed collection is retried in the next run.
- Added support for IPv6, CIDR, DomainGlob, Email and Cryptocurrency Address indicators, and the TLP marking published by ThreatMon.
- Fixed an issue where IP addresses (with or without a port), URLs and Ethereum wallets that ThreatMon publishes as domain names were ingested with an incorrect indicator type.
- Added the ***threatmon-get-collections***, ***threatmon-get-fetch-state*** and ***threatmon-reset-fetch-state*** commands.
- Added the *collection* argument to the ***threatmon-get-indicators*** command.
- Deprecated the *Data Type to Fetch* and *Maximum number of indicators per fetch* parameters. Use the *Collections* and *Maximum pages per fetch* parameters instead.
- Updated the Docker image to: *demisto/python3:3.12.15.14069087*.
