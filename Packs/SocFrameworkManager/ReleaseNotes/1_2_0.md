
#### Integrations

##### SOC Framework Pack Manager

- Changed **socfw-install-pack** to install the pack ZIP directly instead of rebuilding it through the demisto-sdk before upload. The rebuild constructed a content graph on every install; measured end to end against a live tenant, a single-rule pack took 63 seconds via the rebuild and 27 seconds installing the ZIP as-is. On tenants where the integration container's command timeout is tighter than the rebuild, the install was exhausting the budget and dying part-way with no actionable error.
- Added the **use_sdk** argument to **socfw-install-pack** (default **false**) to restore the previous demisto-sdk rebuild path for a pack that requires it, without redeploying the integration.
- Fixed **socfw-install-pack** reporting a successful install for an upload that did not take. The command now reads the tenant's installed pack version after upload and compares it against the version in the ZIP filename, raising an error naming both versions when they disagree. Previously an upload that left the tenant on its existing version returned "installed successfully", so a pack that never upgraded was indistinguishable from one that did, and reinstalling produced the same misleading result.
