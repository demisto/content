
#### Integrations

##### SOC Framework Pack Manager

- Added the **use_sdk** argument to **socfw-install-pack**, selecting between the demisto-sdk install path and a direct upload of the pack ZIP, so the path can be changed without redeploying the integration. The demisto-sdk path is the default and is the one that installs a pack's content items.
- Fixed **socfw-install-pack** reporting a successful install for an upload that did not take. The command now reads the tenant's installed pack version after upload and compares it against the version in the ZIP filename, raising an error naming both versions when they disagree. Previously an upload that left the tenant on its existing version returned "installed successfully", so a pack that never upgraded was indistinguishable from one that did, and reinstalling produced the same misleading result.

#### Scripts

##### SOCFWPackManager

- Fixed **SOCFWPackManager** reporting a successful install when a pack failed to upgrade. On an error from **socfw-install-pack** the script asked the tenant for a second opinion, but only checked whether the pack id was present — which is always true on an upgrade, whatever version the tenant is actually running. A failed upgrade was therefore indistinguishable from a successful one, and the tenant kept serving the older content. The check now compares the installed version against the version in the release filename, an install that reports it did not take is no longer retried as if it were ambiguous, and the version is read back once more before the success line is printed. A verified install now reports the version it landed at.
